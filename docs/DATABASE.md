# PostgreSQL / Neon

Проект пользователя: divine-glitter-19018737; указанная ветка: br-odd-resonance-b4p4teol. Credentials читаются только из локального ENV.

Drizzle schema и версионируемые миграции: клиенты, данные рождения, карты, консультации, статьи, категории, справочники и audit log. Все таблицы приложения изолированы в PostgreSQL schema `astrowed`. Миграции не запускаются автоматически при старте. Результаты вычислений — JSONB snapshot; сущности и связи — нормализованные колонки и FK.

Перед миграцией нужно проверить окружение и предпочесть отдельную dev-ветку Neon. Существующие таблицы не изменяются и не удаляются. API закрытого кабинета требует сессию. Для SaaS необходим отдельный этап tenant isolation и полноценные роли.

В первой рабочей версии миграция и начальное наполнение применены к указанной пользователем ветке, внутри schema `astrowed`. Отдельная ветка Neon не создавалась: доступный MCP-коннектор не передавал обязательный `project_id`, поэтому использовано прямое подключение PostgreSQL из локального ENV. Существующая schema `neon_auth` не изменялась; подключение Neon Auth к приложению остаётся отдельной задачей.
